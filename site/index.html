Data die zichzelf uitlegt

Een kleine kennisgraaf over België: gewesten, provincies, gemeenten, rivieren en personen. Het verschil met een gewone database: de betekenis van de data staat mee in de data. Daardoor kan een computer zelf nieuwe feiten afleiden en fouten opsporen.

Wat de redeneerder doet

Transitiviteit

De data zegt: Gent ligt in Oost-Vlaanderen en Oost-Vlaanderen ligt in het Vlaams Gewest. Omdat sem:ligtIn transitief is, volgt: Gent ligt in het Vlaams Gewest.

Inverse en domein

De data zegt: Provincie Luxemburg heeft als hoofdstad Aarlen. Uit de inverse en het domein volgt: Aarlen is een Hoofdstad, zonder dat iemand het intypte.

Probeer de query →

Symmetrie

De data zegt: Henegouwen grenst aan Namen. Omdat grenzen symmetrisch zijn, volgt: Namen grenst aan Henegouwen.

Probeer de query →

Subeigenschappen

De Zenne mondt uit in de Dijle, de Dijle in de Rupel, de Rupel in de Schelde. Dus de Zenne behoort tot het stroomgebied van de Schelde.

Probeer de query →

Elke naam is een adres

Elk ding in de graaf heeft een IRI die je kunt openen, zoals …/id/antwerpen. Je krijgt een leesbare pagina met machineleesbare JSON-LD erin, en dezelfde gegevens als Turtle, JSON-LD of N-Triples. Dat is Linked Data.

Klik op een knoop om te zien wat de graaf erover weet.

Bevraag de graaf met SPARQL

De query draait in je browser, in Oxigraph (gecompileerd naar WebAssembly). Er is geen server: de site is volledig statisch.

Ook schrijven kan

Probeer een SPARQL UPDATE, bijvoorbeeld:

PREFIX sem: <https://mpparsley.github.io/hello-semantica/def#>
PREFIX kg:  <https://mpparsley.github.io/hello-semantica/id/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
INSERT DATA {
  kg:ieper a sem:Stad ; rdfs:label "Ieper"@nl ;
           sem:ligtIn kg:west-vlaanderen ; sem:inwoners 35000 .
}

De wijziging leeft alleen in je browser. Let op: de redeneerder draait tijdens de build, dus voor Ieper worden in de browser geen nieuwe feiten afgeleid. Vraag je daarna wie in Vlaanderen ligt, dan ontbreekt Ieper. Precies daarom hoort redeneren in de pijplijn.

Validatie met SHACL

Een ontologie zegt wat iets betekent. SHACL zegt waaraan data moet voldoen. De GitHub Actions-build valideert de kennisgraaf bij elke push en weigert te publiceren als er een regel geschonden wordt.
